Qu'est-ce qui fait que,
même en changeant les outils,
on reconnaît immédiatement Grimoire ?

# ADN Grimoire

## Pourquoi ce document existe

L'ADN Grimoire regroupe les principes fondamentaux du projet.

Contrairement aux choix techniques, aux applications ou à l'architecture, ces principes ont vocation à rester stables dans le temps.

Ce document répond à une question simple :

> Qu'est-ce qui fait que Grimoire reste Grimoire, même lorsque les outils évoluent ?

---

# 1. Workflow First

Le workflow prime toujours sur l'apparence.

Les décisions doivent être prises dans l'ordre suivant :

1. Usage quotidien
2. Ergonomie
3. Cohérence
4. Documentation
5. Esthétique

Le but n'est pas de produire un showcase visuel.

Le but est de fournir un environnement agréable à utiliser plusieurs heures par jour.

---

# 2. Guidé mais jamais verrouillé

Grimoire recommande.

Grimoire n'impose pas.

Le projet doit proposer des choix raisonnés, documentés et cohérents.

L'utilisateur conserve toujours la possibilité de remplacer les composants proposés.

Le rôle de Grimoire est de guider, pas de contrôler.

---

# 3. Comprendre avant personnaliser

Le parcours utilisateur recherché est :

Installer

↓

Comprendre

↓

Modifier

↓

S'approprier

La personnalisation ne doit jamais dépendre de mécanismes opaques.

L'utilisateur doit pouvoir comprendre progressivement ce qu'il utilise.

---

# 4. Francophone First

Grimoire est pensé en priorité pour les utilisateurs francophones.

L'objectif n'est pas d'exclure les autres communautés.

L'objectif est de réduire une friction réelle :

la documentation Hyprland et Wayland est majoritairement disponible en anglais.

Grimoire cherche à rendre cet écosystème plus accessible grâce à une documentation claire et compréhensible.

---

# 5. AZERTY First

Les choix ergonomiques doivent prendre en compte les utilisateurs AZERTY dès la conception.

Les raccourcis clavier doivent être :

* cohérents
* mémorisables
* adaptés aux claviers francophones
* indépendants autant que possible des symboles produits

La logique physique des touches doit être privilégiée.

---

# 6. Laptop First

Grimoire est pensé pour un usage quotidien sur ordinateur portable.

Les décisions doivent rester compatibles avec :

* les écrans de taille modérée
* les claviers compacts
* les trackpads
* la mobilité

Le projet ne doit pas dépendre d'un setup multi-écrans complexe pour offrir une bonne expérience.

---

# 7. Transparent et Hackable

Grimoire ne doit jamais devenir une boîte noire.

L'utilisateur doit pouvoir :

* ouvrir les fichiers
* comprendre les configurations
* suivre les dépendances
* modifier le comportement du système

La transparence est une valeur fondamentale.

L'utilisateur doit pouvoir apprendre en explorant le projet.

---

# 8. Réel avant marketing

Le workflow réel est plus important que les captures d'écran.

L'authenticité est plus importante que la mise en scène.

Le projet doit montrer :

* son utilisation réelle
* ses réussites
* ses limites
* ses erreurs
* son évolution

Le but n'est pas de vendre un rêve.

Le but est de partager une expérience de travail réelle.

---

# 9. L'utilisateur avant la technologie

Les décisions doivent être prises en fonction de l'utilisateur avant d'être prises en fonction de la technologie.

Une solution techniquement élégante mais difficile à comprendre n'est pas automatiquement une bonne solution.

L'expérience humaine reste prioritaire.

---

# 10. Le persona fondateur

Grimoire est construit pour le "Jonathan de l'époque".

Une personne :

* curieuse
* motivée
* débutante sur Hyprland
* souhaitant apprendre
* pas forcément à l'aise avec l'anglais technique
* cherchant à comprendre ce qu'elle installe

Chaque nouvelle fonctionnalité doit être évaluée à travers cette question :

> Est-ce que cela aurait aidé le Jonathan qui découvrait Hyprland ?

Si la réponse est non, cette fonctionnalité n'appartient probablement pas au cœur de Grimoire.

---

# Test ADN

Si un utilisateur remplace :

* son terminal
* son shell
* son navigateur
* son éditeur
* son gestionnaire de fichiers

et que l'expérience reste cohérente,

alors l'ADN Grimoire est préservé.

Si Grimoire cesse d'exister dès qu'une application est remplacée,

alors Grimoire n'est qu'une collection de dotfiles.

---

# Résumé

Grimoire n'est pas défini par ses applications.

Grimoire est défini par :

* son workflow
* sa pédagogie
* sa documentation
* son ergonomie
* sa philosophie
* sa cohérence

Les outils peuvent évoluer.

L'ADN doit rester.
