# Le parcours utilisateur Grimoire

## Pourquoi ce document existe

Grimoire ne cherche pas uniquement à installer Hyprland.

Grimoire cherche à accompagner l'utilisateur dans sa découverte, sa compréhension et son appropriation progressive de son environnement.

Ce document décrit le parcours utilisateur idéal visé par le projet.

---

# Vision générale

Le parcours Grimoire n'est pas :

Découverte

↓

Installation

↓

Fin

Le parcours recherché est :

Curiosité

↓

Découverte

↓

Installation

↓

Compréhension

↓

Personnalisation

↓

Appropriation

↓

Transmission

---

# Phase 1 — Curiosité

L'utilisateur découvre Hyprland.

Sources possibles :

* YouTube
* Reddit
* GitHub
* Blogs
* Vidéos de workflow
* Recommandations

Il est souvent attiré par :

* la fluidité
* le clavier
* la productivité
* l'esthétique

Mais il ne comprend pas encore l'écosystème.

---

# Phase 2 — Découverte

L'utilisateur commence à explorer.

Il découvre :

* Hyprland
* Waybar
* Rofi
* Hyprlock
* SwayNC
* Wayland

À ce stade, il est souvent confronté à plusieurs difficultés :

* documentation dispersée
* documentation anglophone
* vocabulaire technique
* nombreuses configurations différentes

L'objectif de Grimoire est de réduire cette friction.

---

# Phase 3 — Installation

L'utilisateur installe Grimoire.

Le projet doit proposer une expérience guidée.

L'objectif n'est pas d'exposer immédiatement toute la complexité du système.

L'utilisateur doit pouvoir commencer rapidement.

Les profils envisagés :

* Débutant
* Avancé
* Personnalisé

Le but est de guider sans enfermer.

---

# Phase 4 — Compréhension

Cette étape constitue le cœur du projet.

L'utilisateur commence à comprendre :

* les keybinds
* le workflow
* l'architecture
* les applications utilisées
* les choix techniques

Il comprend progressivement :

* ce qui existe
* pourquoi cela existe
* comment cela fonctionne

L'objectif n'est pas seulement d'utiliser le système.

L'objectif est de le comprendre.

---

# Phase 5 — Personnalisation

Une fois les bases comprises, l'utilisateur commence à adapter l'environnement à ses besoins.

Exemples :

* changement de terminal
* changement de shell
* changement de navigateur
* changement d'éditeur
* ajustement des workflows
* personnalisation visuelle

Cette étape doit rester simple et documentée.

La personnalisation ne doit jamais dépendre d'une architecture opaque.

---

# Phase 6 — Appropriation

C'est l'objectif principal de Grimoire.

L'utilisateur ne se contente plus d'utiliser une configuration.

Il possède désormais son environnement.

Le système n'est plus :

"Le setup de quelqu'un d'autre."

Il devient :

"Mon environnement de travail."

L'utilisateur comprend :

* ce qu'il utilise
* pourquoi il l'utilise
* comment le modifier

---

# Phase 7 — Transmission

L'étape ultime.

L'utilisateur commence à aider d'autres personnes.

Il partage :

* son expérience
* ses découvertes
* ses améliorations
* ses bonnes pratiques

Il contribue à son tour à réduire la friction pour les nouveaux arrivants.

À ce stade, l'utilisateur reproduit exactement ce qui a motivé la création de Grimoire.

---

# Principe fondamental

Grimoire ne cherche pas à produire des utilisateurs dépendants du projet.

Grimoire cherche à produire des utilisateurs autonomes.

Le succès de Grimoire n'est pas mesuré par le nombre de personnes qui utilisent exactement la même configuration.

Le succès de Grimoire est mesuré par le nombre de personnes qui comprennent suffisamment leur environnement pour le faire évoluer elles-mêmes.
